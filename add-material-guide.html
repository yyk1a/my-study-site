如何添加新资料 · 资料站使用指南

更新于 2026-09-27 · 适用站点 yyk1a.github.io/my-study-site

概览：从一个孤零零的 HTML 文件到上线

设定一个最常见的场景：你手上只有一个 HTML 文件（比如 我的笔记.html），电脑里没有网站仓库、没装 git、也连不上 GitHub 命令行。没关系——全程用浏览器就能搞定，一共 7 步：

步骤做什么在哪做
0体检文件：确认自包含、无外部依赖、UTF-8 编码本地
1起个合规的英文文件名本地
2搭一个和线上一模一样的文件夹结构本地
3从 GitHub 下载最新的 index.html浏览器
4在 index.html 里加一张入口卡片本地
5本地双击验收：点卡片能跳才算数本地
6GitHub 网页上传 + Commit浏览器
7等 1~2 分钟，线上验证浏览器

本质上只做了 两件事：① 把内容页放进 materials/ 文件夹；② 在首页 index.html 的 <div class="grid"> 里加一张指向它的卡片。其余步骤都是为了让这两件事做得稳。

关键提醒："复制卡片"只是给首页加一个入口/封面，并不会凭空生成内容页。内容页必须自己先准备好（或让我帮你生成）。两者缺一，点卡片就会 404。

第 0 步：体检你的 HTML 文件

先别急着上传。在自己电脑上能打开 ≠ 放到网上别人也能正常看。花两分钟做四项检查：

① 双击打开，肉眼过一遍

  • 样式在不在？排版乱不乱？图片显不显示？动画/交互能不能用？
  • 现在看到的样子，基本就是上线后的样子——有问题趁现在修。

② 检查是否"自包含"（本站最重要的约定）

  • 在页面上按 Ctrl+U 查看源码，再按 Ctrl+F 搜 http。
  • 如果搜到 <script src="https://cdn...、<link href="https://...、<img src="https://... 这类外部引用，说明这个文件依赖网络：CDN 一抽风，页面就"裸奔"（本站的全等三角形页就踩过这个坑，后来把 Tailwind 和 GSAP 两个库整个内嵌进文件才解决）。
  • 本站的约定是"自包含单文件"：CSS/JS 全部内联，不引用任何 CDN。这样页面打开即读、可离线、可转发，永远不会缺格式。

③ "内容页资源包"怎么办（图片等附件）

如果你的 HTML 引用了本地图片（比如 <img src="图1.png">），光传 HTML 图片会全挂。两种解法：

方案做法适合
A. 内嵌（推荐）把图片转成 base64 直接塞进 HTML 的 src="data:image/png;base64,..."，保持单文件。把文件发给我，我可以帮你转。图片不多、总大小可控
B. 资源文件夹在 materials/ 下建个子文件夹，如 materials/assets/xxx/，图片放进去一起上传，HTML 里写相对路径 assets/xxx/图1.png。图片多 / 体积大

④ 确认编码是 UTF-8

  • 用记事本"另存为"时，编码下拉框选 UTF-8；VS Code 看右下角，显示 UTF-8 即可。
  • 编码不对，上线后中文会变乱码（�）。

第 1 步：起个合规的文件名

  • 用简短英文小写，单词间用连字符 -，例如 ws63.html、triangle-congruence.html、python-venv.html。
  • 避免中文文件名、空格和特殊符号。准确说：GitHub Pages 其实支持 UTF-8 中文文件名，不会乱码；但浏览器会把它 URL 编码成一长串 %E4%BD%A0...，链接又长又难读，部分工具处理非 ASCII 路径也有坑。所以本站约定用英文。
  • 文件名就是网址：materials/python-venv.html 上线后的地址就是 https://yyk1a.github.io/my-study-site/materials/python-venv.html。

第 2 步：在本地搭一个"迷你网站"

在桌面（或任意位置）新建一个文件夹，按和线上一模一样的结构摆放：

my-site-upload\
├── index.html          ← 第 3 步从 GitHub 下载下来放这里
└── materials\
    └── python-venv.html  ← 你改好名的资料文件放这里
为什么要这么折腾？因为线上网站就是这个结构：首页在根目录，资料页都在 materials/ 里。本地 1:1 摆好之后，卡片里的相对路径 materials/python-venv.html 在本地就能点通（第 5 步验收），上传时也不会放错位置。

第 3 步：下载线上最新的 index.html

必须用线上最新的版本！首页是全站共享文件，每次加资料都要改它。如果你拿电脑里某个旧备份来改，上次新增的资料卡片就会被你覆盖掉——线上直接"开倒车"。

方法 A：只取首页（快，推荐）

  • 浏览器打开 https://github.com/yyk1a/my-study-site；
  • 点击文件列表里的 index.html → 点右上角的 Raw 按钮；
  • 在 Raw 页面按 Ctrl+S 保存到 my-site-upload\ 下（保存类型选"所有文件"，文件名 index.html）。

方法 B：整站打包下载（顺便备份）

  • 仓库主页点绿色 Code 按钮 → Download ZIP；
  • 解压后，把里面的 index.html 复制到 my-site-upload\；
  • 想整站留档的话，materials/ 文件夹也可以一起复制过去。

第 4 步：在 index.html 里加一张卡片

用 VS Code（或记事本）打开 my-site-upload\index.html，按 Ctrl+F 搜索 class="grid"，会找到这一块——它就是首页那排卡片的容器：

<!-- 卡片容器：里面每个 <a class="card"> 就是一张卡片 -->
<div class="grid">
  <a class="card" href="materials/ws63.html">
    <span class="badge b-dev">嵌入式 · 星闪</span>
    <h3>WS63 实操手册 · 环境搭建 + 编译烧录</h3>
    <p>WSL + VSCode + Ubuntu 下 WS63 SparkLink 开发……</p>
    <div class="meta">更新于 2026-09-27 · 约 24 KB</div>
  </a>
  <!-- 其它卡片 …（注意：HTML 注释长这样，不是 /* */） -->
</div>

"复制一张卡片"就是：把任意一整段 <a class="card"> … </a> 原样复制，粘贴到 <div class="grid"> 里面、最后一张卡片之后，然后改内容。3 处必改 + 2 处顺手改：

<!-- 新增卡片：①③④ 必改，②⑤ 顺手改 -->
<a class="card" href="materials/python-venv.html">        ① 【必改】链接 = 第 1 步起的文件名
  <span class="badge b-dev">Python · 环境</span>           ② 【顺手】分类文字 + 颜色类（见下表）
  <h3>Python venv 虚拟环境速查</h3>                     ③ 【必改】卡片大标题
  <p>PEP 668 报错怎么办、venv 创建与激活，一篇讲清。</p>   ④ 【必改】灰色说明文字
  <div class="meta">更新于 2026-09-27 · 约 12 KB</div>     ⑤ 【顺手】日期 / 文件大小
</a>

最后再顺手做一件事：在文件里搜 目前收录，把"目前收录 N 份"的数字 +1，然后保存（保持 UTF-8 编码）。

卡片各部分含义

代码页面上长什么样你要改吗
href="materials/..."点击卡片跳去的地址✅ 必须改（第 1 步起的文件名）
<span class="badge b-dev">左上角彩色分类小标签建议改文字；颜色类四选一（见下表）
<h3>卡片大标题✅ 必须改
<p>灰色说明文字✅ 必须改
<div class="meta">底部"更新于…·约 XX KB"建议顺手改日期 / 大小

颜色标签怎么选

左上角小标签的颜色由 badge 后面跟的颜色类决定。目前站点内置 四色，直接复用：

类名颜色适合场景
b-math绿色数学 / 理科类
b-sec橙色信息安全 / 通用
b-dev蓝色开发 / 工程 / 技术
b-guide紫色本指南这类"站点 / 帮助"页
想加第 5 种颜色？在 index.html 的 <style> 区域加一条，比如 .b-ai { background: #db2777; }（粉色，四个内置色都没用它），再把卡片上的类写成 b-ai 即可。颜色值可以是任意合法 CSS 颜色，注意别和已有四色撞色。

第 5 步：本地先验收（最关键、也最常跳过）

上传之前，先在本地完整预演一遍：

  • 双击 my-site-upload\index.html，首页应该出现你新加的卡片，样式和其他卡片一致；
  • 点击新卡片——因为 materials/ 文件夹就在旁边、相对路径本地同样成立，浏览器应该直接打开你的资料页；
  • 再点点老卡片（如果第 3 步用了方法 B 把 materials 整个复制下来了），确认没把旧东西改坏。
这一步的意义：本地点得开 = 文件名和 href 写对了，上线必通；本地点不开（浏览器报"找不到文件"）= 路径或文件名写错了，现在改是免费的，上线后再发现就得重来一轮。

第 6 步：网页上传（本机命令行连不上 GitHub，所以走网页）

  • 浏览器打开 https://github.com/yyk1a/my-study-site；
  • 点 Add file → Upload files；
  • 把 my-site-upload\ 里的 index.html 和 materials 文件夹一起拖进上传区（index.html 覆盖旧版属预期；网页上传只覆盖同名文件，不会删掉仓库里你其它的资料页）；
  • 页面下方点绿色 Commit changes 按钮提交。
网页上传的硬限制：单文件 ≤ 25 MB、单次最多约 100 个文件。日常资料页远达不到这个量级；真遇到了（比如嵌了视频）就得分批传，或者把大文件改放外链/网盘。

第 7 步：线上验证 + 没生效怎么办

  • 提交后等 1~2 分钟（GitHub Pages 不是实时生效）；
  • 打开 https://yyk1a.github.io/my-study-site/，按 Ctrl+F5 强制刷新（绕过浏览器缓存），应看到新卡片；
  • 点新卡片，资料页正常打开 = 全流程完成 🎉；
  • 也可以直接访问 https://yyk1a.github.io/my-study-site/materials/你的文件.html 验证内容页本身。

出问题了对照排查

症状最可能的原因怎么办
首页没有新卡片浏览器缓存；或 index.html 没传成功Ctrl+F5 强刷；回仓库文件列表确认 index.html 的提交时间已更新
点卡片 404内容页没传上去；或 href 文件名和实际文件名大小写不一致线上服务器区分大小写（Notes.html ≠ notes.html），而 Windows 本地不区分——所以本地验收过了上线仍可能 404，逐一核对大小写
页面"裸奔"没样式 / 动画不动HTML 引用了外部 CDN，被网络挡了回第 0 步：把依赖内嵌进文件再传
中文变乱码（�）文件保存时编码不是 UTF-8用 UTF-8 重新保存后再传一次

常见坑 / 检查清单

  • ✅ href 用相对路径：写 materials/你的文件.html。别写成 /materials/...——本项目是"项目站点"，斜杠开头会被解析到 yyk1a.github.io/materials/...，丢掉 /my-study-site 前缀直接 404。完整的 https://... 绝对地址技术上能打开，但本地预览会失效、以后迁移也麻烦，不推荐。
  • ✅ HTML 注释是 <!-- -->，不是 /* */：后者是 CSS/JS 的注释语法，写进 HTML 会原样显示在页面上。
  • ✅ 代码片段里的 < > & 要转义：在页面里贴 HTML 示例时，必须把 < 写成 &lt;、> 写成 &gt;、& 写成 &amp;，否则浏览器会把示例当真实标签"吃掉"。（首页和本指南旧版都踩过这个坑。）
  • ✅ 线上区分文件名大小写：本地 Windows 不敏感，GitHub Pages 服务器敏感，href 与文件名大小写必须完全一致。
  • ✅ 别忘了"目前收录 N 份"+1，否则数量和卡片数对不上。
  • ✅ 内容页和首页都要传：只传首页 → 卡片 404；只传内容页 → 首页看不到入口。
  • ✅ index.html 永远用线上最新版来改，别用旧备份，否则会覆盖掉之前新增的内容。
  • ✅ 等 1~2 分钟 + 强刷：GitHub Pages 不是实时生效，且浏览器会缓存，务必 Ctrl+F5。

懒人方案

把资料（md / 笔记 / 直接说的话）发给我，告诉我想要的标题和一句说明，我直接帮你：生成自包含内容页 + 改好首页卡片 + 产出"上传包"文件夹，你只要按第 6 步去 GitHub 网页拖一下、点 Commit 就行。
