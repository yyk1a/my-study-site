一、核心心智模型（先记住）

整条链路只有四步，记住它就不容易乱：

menuconfig 决定「编谁」  →  你改的 main.c 决定「干什么」
      →  编译打包成固件   →  烧录装进板子
⚠ 注意
两个最容易踩的坑，先预警：
1. 同一章的 demo 是单选：你不进 menuconfig 切换，编译出来的永远是默认那个（hello world）。
2. menuconfig 切了 demo 之后，直接增量编译往往还是编出旧的那个——旧的编译产物还躺在缓存里，CMake 没重新评估「该把哪个文件夹编进固件」。所以切完 demo 必须 -c 清理后再编译（见第五节）。

三、从零搭建环境（首次配置必做）

3.1 第一个坑：`externally-managed-environment`

现象：sudo pip install xxx 报 error: externally-managed-environment。

原因：Python 3.11 / Ubuntu 23.04 起启用 PEP 668，系统自带 Python 被标记为「由 apt 托管」，禁止 pip 往系统目录写包，避免破坏系统工具依赖。你的 Python 3.14 触发了它。这是保护机制，不是故障。

📌 说明
核心结论：书的老写法 sudo pip install xxx 在旧 Ubuntu 能用，在你这新版系统已失效，要改用下面的正确渠道（apt / pipx / venv）。

3.2 判断：这个包该走 apt 还是 pip / pipx / venv？

类型例子安装方式
系统级构建工具（命令行程序）cmake、gcc、gitsudo apt install
Python 命令行工具（独立 app）kconfiglib 当命令用（menuconfig/guiconfig）pipx install
Python 库（代码里 import 用）kconfiglib（被 build.py import）、pycparservenv + pip install
apt 源里没有的 Python 包kconfiglib、pycparserapt 查不到 → 走 pip / pipx / venv

3.3 工具选型速查（PEP 668 之后）

需求命令说明
装系统程序sudo apt install 包系统级，最稳
装 Python 命令行 apppipx install 包每个工具独立小环境，命令进 PATH
装 Python 库（供 import）python3 -m venv .venv + source .venv/bin/activate + pip install 包build.py 这类脚本必须走这个
应急（不推荐）pip install 包 --break-system-packages绕过保护，有风险，别养成习惯

书里出现的 sudo pip install xxx，在你的系统上统一翻译为：查得到 apt 包 → sudo apt install xxx；查不到 → 若是命令行工具用 pipx install xxx，若是库（会被 import）必须用 venv。

3.4 正确操作流程（本项目完整版）

⚠ 注意
第 0 步：确认终端是 WSL，不是 PowerShell
· 错：PS C:\Users\yyk1a\ws63\sparklink-book>（Windows 路径 + PS 开头）
· 对：yyk1a@LAPTOP-xxx:~/ws63/sparklink-book$（带 $ 结尾、Linux 路径）
· 切换：终端面板 + 右边的 v 下拉 → 选 Ubuntu (WSL)；或直接在 PowerShell 敲 wsl 切入。
· 自检口诀：提示符 PS C:\... 开头 = 错；user@...:~$ 结尾带 $ = 对。
（在 PowerShell 里跑 ./build.py 会被当成 Windows 的 Python 脚本，出现 >>> 交互提示符、出不来 menuconfig 界面。）

第 1 步：进项目目录

cd ~/ws63/sparklink-book

第 2 步：建 venv（独立 Python 环境）并激活

python3 -m venv .venv
source .venv/bin/activate      # 激活后提示符前面出现 (.venv)
📌 说明
venv 隔离的是「Python 运行环境 + 装的库」，你的代码文件原封不动，只是多了个 .venv/ 文件夹。项目 .gitignore 里加 .venv/。
⚠ 路径陷阱：venv 在 ~/ws63/sparklink-book/.venv，不是 ~/ws63。在 ~/ws63 下激活会报 No such file。

第 3 步：在 venv 里装需要的 Python 库

pip install setuptools        # 关键：Python 3.12+ 已删除标准库 distutils，build.py 用的 pkg_resources 依赖它
pip install kconfiglib        # build.py 需要 import kconfiglib
pip install pycparser         # 书里列的，按需（通常会被别的包自动带）
📌 说明
为什么必须装 setuptools：Python 3.12 起官方删除了标准库 distutils，而新建的 venv 默认不预装 setuptools。书里的 build.py 通过 pkg_resources（属于 setuptools）调用 distutils，缺了就报 ModuleNotFoundError: No module named 'distutils'。新版 setuptools 自带 distutils 兼容实现，装上即补齐。

pipx 与 venv 的区别（关于 kconfiglib / pycparser）：
· kconfiglib 既是命令行工具（pipx 的完美适用对象），又是 build.py 要 import 的库。pipx 把它隔离在小房间里，命令行能用，但脚本 import 不到——所以必须用 venv 装。
· pycparser 本质是个「库」（解析 C 代码，通常是 cffi 的依赖），用 pipx 装能成功、书上的检查也能过，但它一般不需要你手动装，后面哪个工具真正需要它时会自动带进来。若书上报「缺少 pycparser」，在那个工具自己的环境里装即可。

之后若 build.py 再报 ModuleNotFoundError: No module named 'xxx'，保持 (.venv) 激活，继续 pip install xxx（常客还有 pyyaml 等）。老 SDK 在新 Python 上跑，基本就是「缺什么补什么」。之前 pipx 装的 kconfiglib 不用删，留着没影响。

第 4 步：跑 menuconfig

./build.py menuconfig ws63-liteos-app

终端清屏，出现蓝黄边框的 Kconfig 配置界面即成功。

✅ 提示
以后每次开新终端，固定三连：
cd ~/ws63/sparklink-book
source .venv/bin/activate # 看到 (.venv) 才算就绪
./build.py menuconfig ws63-liteos-app
（不想激活就退而求其次用 ~/.venv/bin/python build.py ...，但激活更省心。）

四、menuconfig 操作指南

4.1 切换你要编的 demo（换实验必做，否则白编）

终端执行 ./build.py menuconfig ws63-liteos-app 后，终端变成蓝黄边框菜单：

  • ↓ 移到 Application → 回车 → ch2 samples
  • ↑↓ 移到你要的 demo（例：Support LED Demo.）
  • 按 空格 选中（单选：hello world 的勾会自动消失）
  • S 保存 → Q 退出

这一步写进 .config，决定编译时把哪个文件夹加进固件。如果你一直做同一个 demo、且当初已勾过，可跳过本步。

⚠ 注意
光做 menuconfig 还不够：今天 LED 菜单切对了、编译也跑完了，板子却还是 hello world。根因是增量编译没刷新构建图——CMake 重新生成了配置头文件、重新打包，却没重新决定「把哪个 demo 编进固件」，hello world 的旧产物原封不动留在库里。所以切完 demo，必须紧跟第五节的 -c 清理，否则白切。

4.2 menuconfig 界面按键（纯键盘，鼠标无效）

按键作用
↑ ↓上下移动高亮条
Enter进入 ---> 结尾的子菜单
Esc 连按两次返回上一级
空格 / Y切换选项开 / 关
/搜索配置项
S保存配置
Q退出（改动后按两次确认）

改完记得 S 保存 再 Q 退出，否则不生效。

五、编译（你只敲一条命令 —— 但切过 demo 时要先清理）

保持 (.venv) 激活状态下执行：

./build.py -j1 ws63-liteos-app
  • 编译到 [100%] 即成功，最后会打印固件路径，通常在：output/ws63-liteos-app/firmware/bin/ 下的 .fwpkg / .bin
  • 中途若报 ModuleNotFoundError: No module named 'xxx'：保持 (.venv) 激活，pip install xxx 再重编
  • 黄色 SyntaxWarning 无视（老代码在新 Python 上的无害告警）
⚠ 注意
切换 demo 后必须 -c 清理重编（这是 LED 不生效的根因）：
./build.py -c ws63-liteos-app # 清掉整个 output 下的旧构建缓存
./build.py -j1 ws63-liteos-app # 全量重编（会花十几分钟，正常）
第一次全新构建会自动全量配置，所以之前没遇到；但改过 menuconfig 之后是增量编译，CMake 不会重新把目标 demo 加进编译图。不清缓存 → 编出来的还是旧 demo（hello world）。所以「换实验」的标准流程是 menuconfig 切换 → -c 清理 → -j1 编译 三步缺一不可。

六、烧录（在 Windows 侧做，板子插在 Windows 上）

  • 插板子：Type-C 怼到底听到/感到「咔哒」，别只看红灯亮就以为到位（今天红灯亮但没插紧，导致设备识别失败）
  • 确认 COM 口：设备管理器 → 「端口 (COM 和 LPT)」出现 USB-SERIAL CH340 (COMx)，记下 COM 号
  • 选固件：用烧录工具时，文件选 WSL 里的产物，直接在工具的文件框输：
    \\wsl$\Ubuntu\home\yyk1a\ws63\sparklink-book\output\ws63-liteos-app\firmware\bin\...
    （不用把固件拷到 Windows）
  • 烧录：选对应 COM → 点烧录 → 按工具提示（通常按板子 RESET 键或重新插拔）开始下载，进度条走完即成功
⚠ 注意
必须烧本次新编译的固件，不能烧旧的 bin —— 改了 demo 不重编、只重烧旧文件，板子还是跑老程序。

七、完整操作序列（照抄版）

# —— 编译侧（WSL Ubuntu 终端） ——
cd ~/ws63/sparklink-book          # 进工程（不是 ~/ws63）
source .venv/bin/activate         # 激活，看到 (.venv)
./build.py menuconfig ws63-liteos-app   # 切 demo：空格选中目标，S 保存 Q 退出
./build.py -c  ws63-liteos-app    # 切过 demo 才需要：清旧缓存
./build.py -j1 ws63-liteos-app    # 编译

# —— 烧录侧（Windows） ——
# 设备管理器确认 COMx → 烧录工具选 \\wsl$\... 下新固件 → 选 COM → 烧录 → 按 RESET

九、目录与文件路径说明（防迷路）

  • 活工程（编译用的）：WSL ~/ws63/sparklink-book，含 build.py、.venv。改代码、编译、开终端一律用这一份。
  • Windows 旧镜像：已改名 C:\Users\yyk1a\ws63\_backup_sparklink-book_win，只用来看代码、不要编译它，免得「A 份改了、B 份编了」。
  • 烧录用 \\wsl$ 路径取活工程的产物，不用把固件拷到 Windows。

十、一句话总结

✅ 提示
系统工具（cmake）走 apt；Python 命令行工具走 pipx；被 build.py import 的库（kconfiglib）必须放进 venv；一切命令在 WSL Ubuntu 终端里跑，别在 PowerShell。换实验的标准动作是 menuconfig 切换 → -c 清理 → -j1 编译 → Windows 烧录新固件。
