1. 研究问题

核心问题：为什么原生 Transformer 在时序预测上长期打不过线性模型（DLinear 等），以及如何在不修改任何 Transformer 组件的前提下让它重新成为 SOTA？

论文诊断出传统用法（"时间点当 token"）的致命缺陷：

  • 时间 token 语义混淆：把同一时间戳上所有变量的取值融合进一个 embedding。不同变量是完全不同的物理量（温度、湿度、电流……），融合后的 token 语义混乱，注意力图无意义。
  • 组件职责错配：注意力机制本就擅长建模集合元素间的相关性 → 应学变量间关联而非相邻时间点的冗余关联；FFN 本就是逐 token 非线性变换器 → 应学单个变量整段序列的时间表示。
  • 长回看窗口退化：时间点当 token 导致序列越长注意力开销越大、性能反而下降。
解法一句话：倒置（Inversion）——把每个变量的整段历史序列压缩成一个 token，让注意力在 N 个变量 token 之间做，让 FFN 在每个变量 token 内部做时间建模。

2. 方法架构

总体数据流

输入 x ∈ R^(B×T×N)          (B=batch, T=回看长度96, N=变量数)
        │ transpose(-2,-1)
        ▼
x' ∈ R^(B×N×T)              每一行 = 某个变量的整段历史
        │ Variate Embedding: Linear(T → d_model)
        ▼
H ∈ R^(B×N×d)               N 个"变量 token"
        │ × L 层标准 Transformer Encoder
        │   ├── MHSA(H)   ←注意力在 N 个变量间，学互相关
        │   └── FFN(H)    ←FFN 逐变量独立，学时间模式（共享权重）
        ▼
H' ∈ R^(B×N×d)
        │ Prediction Head: Linear(d → H_pred)
        ▼
Y ∈ R^(B×N×H_pred)          每个变量的未来 H_pred 步
        │ transpose(-2,-1)
        ▼
ŷ ∈ R^(B×H_pred×N)          预测输出

模块 1：Variate Embedding（倒置嵌入）

  • 输入先转置成 B×N×T，再对每个变量的 T 维序列做一次线性投影 Linear(T → d)；
  • 得到 N 个 token，每个 token 是一个变量的"全局画像"，而非一个时间点的"多变量快照"；
  • LayerNorm 作用在每个 token（时间维）上 ≈ 对每条序列做软归一化，缓解分布漂移；数据层面对每个变量独立 StandardScaler。

模块 2：复用原生 Transformer Encoder（组件零改动）

  • MHSA：注意力矩阵为 N×N（变量×变量），显式学习多变量关联——多变量数据集（Electricity 321 变量、Traffic 862 变量）收益最大；
  • FFN：Linear(d→d_ff) → GELU → Linear(d_ff→d)，逐 token 独立作用且跨变量共享——等价于用一个共享 MLP 对每个变量的时间序列做非线性特征提取；
  • pre-LN 残差结构堆叠 L 层。

预测头：Linear(d → H_pred)，把每个变量 token 直接投影为未来 H_pred 步预测。

参数量与复杂度

项目表达式典型值（ETTh1, d=128）
参数量N×T×d（嵌入）+ L×(4d²+2d·d_ff)（编码器）+ N×d×H（头）约 0.5M
注意力复杂度O(N²·d)（与 T 无关）N=7 时可忽略
前向显存注意力矩阵 B×heads×N×NTraffic(N=862) 时需注意
关键洞察：倒置后注意力的平方复杂度从"时间维"转移到"变量维"。ETT 只有 7 个变量，注意力几乎免费——这就是它对任意回看长度 T 都友好的原因。

统一协议（与此前工作对齐）

  • 回看窗口 T = 96（ILI 例外，T = 36）；
  • 预测长度 H ∈ {96, 192, 336, 720}（ILI: {24, 36, 48, 60}）；
  • 指标：MSE / MAE，均在逆归一化后的原始量纲上计算；
  • 测试协议：滑动窗口 stride = 1 滚动预测；每配置 3 个随机种子取平均；
  • 损失函数：MSE；优化器：Adam。

Baselines

PatchTST、TimesNet、DLinear、Crossformer、FEDformer、Autoformer、Informer、原版 Transformer、N-BEATS 等。核心叙事：iTransformer 在几乎全部数据集上超过线性模型 DLinear 与此前最强 Transformer 变体 PatchTST。

论文核心结论（复现要验证的靶子）

  1. 多变量数据集（ECL/Traffic/Weather）上显著优于时间 token 化的各 Transformer 变体；
  2. 回看窗口越长性能越好（与 PatchTST 等相反）；
  3. 变量间注意力学到的相关性可解释（可视化注意力图）；
  4. 跨变量泛化：部分变量训练后可推广到未见过的变量。

5. 核心算法伪代码

Algorithm: iTransformer 前向（训练与推理一致）
────────────────────────────────────────────────────────
输入: x ∈ R^(B×T×N)        # 标准化后的历史窗口
超参: L(层数), d(d_model), H(预测长度)

1  x_inv ← transpose(x, (0, 2, 1))          # B×N×T，"倒置"
2  Z ← Linear_{T→d}(x_inv)                   # B×N×d，变量 token
3  for l = 1 .. L:                           # pre-LN Encoder
4      Z ← Z + MHSA(LN(Z))                   # 注意力: N×N 变量间相关
5      Z ← Z + FFN(LN(Z))                    # FFN: 逐变量时间建模
6  Z ← LN_final(Z)
7  Y ← Linear_{d→H}(Z)                       # B×N×H
8  ŷ ← transpose(Y, (0, 2, 1))               # B×H×N
9  return ŷ

训练: minimize MSE(ŷ, y) 在标准化空间；
评测: inverse_scale(ŷ) 后与原始量纲真值计算 MSE/MAE。
────────────────────────────────────────────────────────
# 消融时最常用的两把"手术刀"：
#   · 第 4 行换成对时间维注意力  → 退化成原版 Transformer（验证"倒置"贡献）
#   · 删除第 4 行（只留 FFN）    → 退化成逐变量 MLP（验证变量注意力贡献）

6. 复现难点（7 条）

#难点具体风险缓解策略
1归一化与逆归一化的维度per-variate StandardScaler 必须只在训练段拟合；逆变换时 (B,H,N) 与 scaler 的 axis 对齐极易写错单元测试：inverse(scaler.transform(x)) ≈ x
2数据划分边界ETT 按月划分（12/4/4），验证/测试段起点要向前多留 T-1 个点；写错边界系统性偏离论文 5%~30%直接对照官方 data_loader.py 的 border1s/border2s
3Traffic/ECL 显存峰值注意力矩阵 B×8×862×862，float32 下 batch=32 约 750MB，8GB 卡易 OOMbatch 降到 8~16；或梯度累积
4评测协议测试滑窗 stride 必须=1；指标必须在逆归一化后算对照官方 exp/exp_main.py 的 test 循环
5与 baseline 公平比较必须 T=96 统一、三次种子取平均实验脚本化，避免手工改参偏差
6超参细节d_ff=d_model（非 4×）、pre-LN、末端 LN——任一不对齐，ETTh2 可能差 0.01+ MSE逐行核对官方 models/iTransformer.py（约 60 行）
7ILI 小数据集过拟合仅 966 点，early stopping 判断不准patience 严格=3，验证集 loss 选最优 checkpoint

验证论文结论的步骤（主线，5 步）

Step 1｜环境与数据体检（0.5 天）

  • 装 PyTorch（8GB 卡注意 cu128 轮子）；下载 8 个数据集到 datasets/；
  • 跑 python -m data.preprocess --dataset ETTh1：核对行数、变量数、NaN，打印三段边界并与官方 data_loader.py 逐项比对；
  • 通过标准：ETTh1 边界 = train(0, 8640) / val(8544, 11520) / test(11424, 14400)。

Step 2｜单点复现：ETTh1 96→96（0.5 天）

  • 默认配置训练 1 个种子；记录 test MSE/MAE；
  • 通过标准：MSE 落入论文值 ±10% 相对误差区间（见预期结果表）；
  • 未达标 → 先查失败排查清单，禁止立刻调参"凑数"。

Step 3｜横向扩展：数据集 × horizon 矩阵（1~1.5 天）

  • 优先级（算力友好）：ETTh1 → ETTh2 → ETTm2 → Weather → ECL → ETTm1 → Traffic → ILI；
  • 每数据集 4 个 horizon {96, 192, 336, 720}；超参见论文分析页 §4。

Step 4｜稳定性：三种子协议（0.5 天）

  • 对 ETTh1 / ETTh2 / Weather / ECL 每配置补齐 3 个种子，报告 mean±std；
  • 通过标准：std/mean < 5%（ETTh2 波动天然偏大可放宽到 8%）。

Step 5｜结论级验证（0.5 天）

  • C2：ETTh1 上回看长度 T ∈ {48, 96, 192, 336, 512} 扫描（消融 A5）；
  • C4：取 ECL 训练后模型，导出 321×321 平均注意力矩阵热力图，观察变量簇。

数据划分协议（写 get_split_bounds 的唯一依据）

这是复现中最容易系统性出错的一环：ETT 系列按"月"划分（12 月训练 / 4 月验证 / 4 月测试），其余数据集按 0.7 / 0.1 / 0.2 比例；验证/测试段起点必须向前回退 T 个点。
ETTh1/ETTh2（小时级，1 天 = 24 点）:
    border1s = [0, 12*30*24 - T, (12*30+4*30)*24 - T]
    border2s = [12*30*24, (12*30+4*30)*24, (12*30+8*30)*24]

ETTm1/ETTm2（15 分钟级，1 天 = 96 点）:
    上述边界全部 × 4

Weather / ECL / Traffic / ILI:
    num_train = int(n * 0.7); num_test = int(n * 0.2)
    num_val   = n - num_train - num_test
    border1s = [0, num_train - T, n - num_test - T]
    border2s = [num_train, num_train + num_val, n]

单元测试锚点: ETTh1 (n=17420, T=96) 的边界应恰为
    train (0, 8640), val (8544, 11520), test (11424, 14400)
